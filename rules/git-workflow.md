# Git Workflow Rules

- Inspect Git status before modifying or committing files. Reason: identify existing user changes.
- Never overwrite or discard user work without explicit approval. Reason: prevent data loss.
- Keep changes focused on the assigned task. Reason: simplify review and rollback.
- Use descriptive commit messages when commits are requested. Reason: document the purpose of changes.
- Do not commit or push unless requested or explicitly required by the approved workflow. Reason: preserve user control.
- Never include secrets in commits. Reason: protect credentials.
- Report changed files and relevant Git problems accurately. Reason: maintain a reliable project history.
