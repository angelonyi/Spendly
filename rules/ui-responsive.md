# UI and Responsive Design Rules

- Keep the interface simple and focused on the approved MVP. Reason: protect the project scope.
- Make the add-expense action easy to find. Reason: support the main user task.
- Provide clear navigation to the dashboard, expenses, and budgets. Reason: make core features discoverable.
- Give forms clear labels and understandable validation feedback. Reason: support accurate input.
- Provide loading, empty, success, and error states for relevant operations. Reason: explain application behaviour.
- Require confirmation before permanently deleting an expense. Reason: prevent accidental loss.
- Support desktop and mobile screen sizes. Reason: maintain usability across devices.
- Use semantic interface elements and accessible labels. Reason: improve accessibility.
- Do not add elaborate animations or optional interface features without approval. Reason: keep implementation focused.
