# Code Quality Rules

- Write readable, maintainable TypeScript. Reason: make code easier to understand and change.
- Use clear names for variables, functions, and components. Reason: reduce ambiguity.
- Keep each function and component focused on a clear responsibility. Reason: simplify testing and maintenance.
- Reuse logic when doing so improves consistency. Reason: avoid conflicting implementations.
- Follow existing project conventions unless an approved change is needed. Reason: maintain consistency.
- Do not refactor unrelated code during a focused task. Reason: reduce regression risk.
- Never hide failures with empty catch blocks or silent fallbacks. Reason: make errors discoverable.
- Do not claim code works without verification. Reason: distinguish assumptions from tested results.
