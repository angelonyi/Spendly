# Project Structure Rules

- Inspect the existing project structure before creating or moving files. Reason: avoid unnecessary restructuring.
- Follow the project's existing Next.js conventions. Reason: preserve compatibility.
- Keep UI components, server-side operations, validation, and database access appropriately separated. Reason: make responsibilities clear.
- Create files and folders only when they serve an approved purpose. Reason: keep the MVP small.
- Do not move or rename unrelated files. Reason: reduce regression risk.
- Update affected documentation when an approved structural change makes it inaccurate. Reason: keep project instructions reliable.
